# Typing in progress

Дополнение по заданию `real-time-forum-typing-in-progress__ts.md`.

В открытом личном чате отображаются имя собеседника, текст «печатает» и три плавно анимированные точки. Сигналы передаются через существующий авторизованный WebSocket; новые зависимости не добавлены.

## Поведение

- Сигнал появляется при вводе непустого текста, включая вставку из буфера обмена.
- Пока ввод продолжается, состояние обновляется не чаще одного раза в секунду. Обновления не перезапускают анимацию.
- Через 1,2 секунды без ввода отправляется остановка.
- Очистка поля, отправка сообщения, потеря фокуса, смена собеседника, уход из чата, скрытие вкладки и выход из аккаунта останавливают набор.
- При разрыве соединения сервер отправляет остановку последнему собеседнику. На стороне получателя есть защитное истечение состояния через 4 секунды без обновлений.
- После временного разрыва клиент проверяет сессию и пытается восстановить WebSocket с задержками 1, 2, 4, 8 и 10 секунд. Успешное подключение сбрасывает счётчик попыток; выход из аккаунта отменяет переподключение.
- Ошибка протокола `1002` отображается уведомлением и записывается в консоль браузера. Автоматических повторов при этой ошибке нет: перезагрузите страницу и проверьте причину нарушения протокола. Недействительная сессия с кодом `1008` возвращает на экран входа.
- Имя и ID отправителя сервер определяет по авторизованной сессии. Сигнал получает только выбранный собеседник.
- При системной настройке уменьшения движения точки отображаются без анимации.

## Протокол

Клиент отправляет:

```json
{"type":"typing","data":{"to_user_id":2,"typing":true}}
```

Сервер передаёт собеседнику:

```json
{"type":"typing","data":{"from_user_id":1,"username":"Alice","typing":true}}
```

Для остановки используется `typing: false`. Состояние временное, в базу данных не записывается. Имя пользователя читается один раз при подключении, запросов к базе при каждом нажатии нет.

## Проверка

Из папки `src`:

```powershell
go test ./...
node --test assets/static/app.typing.test.cjs
go run cmd/server/main.go
```

Для SQLite нужен включённый CGO и C-компилятор, как указано в основном README.

1. Открыть `http://localhost:8080` в двух браузерах или обычном и приватном окне, войти под разными пользователями.
2. Открыть взаимные личные чаты. Вводить текст более 10 секунд: у собеседника всё время должны отображаться имя и плавные точки.
3. Остановить ввод: индикатор должен исчезнуть примерно через 1,2 секунды.
4. Проверить очистку поля, отправку сообщения, уход из чата, переключение вкладки и закрытие окна отправителя.
5. Повторить с другого аккаунта. С третьим аккаунтом проверить, что сигналы чужой переписки ему не отображаются.

Go-тесты проверяют реальные авторизованные WebSocket-соединения, адресную доставку, оба направления, повторные сигналы, смену собеседника, отправку сообщения, отключение и некорректные события. Отдельно проверяются WebSocket-кадры при предложении сжатия клиентом и повторное применение SQL с начальными категориями. JavaScript-тесты проверяют обработчики приложения, таймеры, переподключение и обработку кодов закрытия с управляемыми таймерами и моделью DOM.
